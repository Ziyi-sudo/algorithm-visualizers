laicode 176 / 177 · substring vs subsequence

差别只有「不相等时怎么办」这一行

同样两个字符串 s = "abcde"、t = "ace"。相同字符时两者都是继承左上角 +1；不同字符时，子串归零、子序列继承 —— 一行之差，答案从 1 变成 3。

三处差别

　Substring（要连续）Subsequence（不要连续）
相同字符dp[i-1][j-1] + 1dp[i-1][j-1] + 1　← 一样
不同字符0　断了从头再来max(dp[i-1][j], dp[i][j-1])　断了还能继承
看几个大哥1 个（左上）3 个（左上 / 上 / 左）
答案在哪边填边记 globalMaxdp[m][n] 右下角
表的大小不加 padding，手动判 i==0||j==0加一圈 0，(m+1)×(n+1)

为什么答案位置不同 —— 这是最容易混的一处。

Substring：dp[i][j] 的含义是「同时以 s[i]、t[j] 结尾的公共子串长度」。右下角那格只代表「以最后两个字符结尾」这一种情况，最长的那段可能出现在表的任何位置 —— 所以必须全程维护 globalMax。这跟一维 LAS「有过 reset 就必须用 globalMax」是同一条。

Subsequence：dp[i][j] 的含义是「s 的前 i 个 vs t 的前 j 个的公共子序列长度」—— 注意是"前 i 个"不是"以 i 结尾"。它全程只增不减（不相等时继承而非归零），所以右下角一定是最大的。

「加一圈 0」的 padding 技巧（老师注释里那句）：

int[][] dp = new int[s.length() + 1][t.length() + 1];   // 多开一行一列
for (int i = 1; i <= s.length(); i++)
    for (int j = 1; j <= t.length(); j++)
        if (s.charAt(i-1) == t.charAt(j-1))  ...          // 注意 -1

好处：第 0 行第 0 列天然全是 0（Java 默认值），代表"空字符串"
      → dp[i-1][j-1] 永远不越界，不用写 if (i==0 || j==0)
代价：dp 的下标和字符串的下标错开 1 —— charAt 要写 i-1

这就是讲义那条：「i 表示长度 → dp 长度 = input 长度 + 1」
              「跟 string 相关 prefer i 表示 len，能表达 empty string」

跟一维的对照（这才是这张卡真正的价值）：

一维                              二维
LAS  子数组，要连续    look back 1     LCSubstring    不同就归零
LIS  子序列，不要连续  look back all   LCSubsequence  不同就继承

"连续 vs 不连续"这个对立，在一维和二维里是同一个道理：
    要连续 → 断了就没法接，只能从头再来（归零 / 只看紧邻的那个）
    不连续 → 断了还能跳过去接，所以要看更多的前驱

复杂度：两者都是 Time O(s·t)、Space O(s·t)。因为只依赖上一行，空间都能优化到 O(min(s,t))（滚动数组）。

s = "abcde"，t = "ace" · 最长公共子串 "a"（长度 1） · 最长公共子序列 "ace"（长度 3）
