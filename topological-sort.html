依次消灭入度为 0 的点

入度 = 还有几门先修课没上完。入度为 0 = 现在就能上。上完一门，它指向的每门课入度各减 1，减到 0 的就进队列。[a, b] 表示要上 a 得先上 b，所以边的方向是 b → a。

算法本体（Kahn）

  1. 建图 + 统计入度：每条 [a, b] 加一条边 b → a，同时 indegree[a]++。
  2. 所有入度为 0 的点入队——它们没有先修课，一开始就能上。
  3. 出队一个，收进结果；把它指向的每个邻居入度减 1，减到 0 就入队。
  4. 队列空了：结果里有 n 个点 → 成功；少于 n 个 → 有环，返回空数组。
indegree ← int[n];  graph ← n 个空列表

对每条 [a, b]:
    graph[b].add(a)          ← 边的方向:先修课指向后续课
    indegree[a]++

队列 ← 所有 indegree[i] == 0 的 i

队列非空:
    cur ← poll();  result.add(cur)
    对 graph[cur] 里每个 nei:
        indegree[nei]--
        indegree[nei] == 0 → offer(nei)      ← 减到 0 才入队

result.size() == n → 返回 result
否则 → 返回空数组                            ← 有环

为什么"减到 0 才入队"而不是"减了就入队"：入度 3 的课有三门先修，减一次只说明少了一门，还不能上。只有归零那一刻才真正解锁 —— 而且那一刻只会发生一次，所以每个点只入队一次，不需要额外的 visited。

为什么剩下的点就是环：环上的每个点都在等环里的另一个点，入度永远减不到 0，谁也进不了队列。队列空了但还有点没出来 —— 那些点必定卡在环里。

答案不唯一：队列里同时有多个入度为 0 的点时，先取谁都行 —— 它们之间没有依赖关系。所以 [0,1,2,3] 和 [0,2,1,3] 都对。
