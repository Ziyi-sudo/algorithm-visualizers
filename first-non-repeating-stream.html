一个字符的三种状态

状态在 singled 里在 repeated 里在链表里
1. 还没出现过✗✗✗
2. 只出现过一次✓✗✓
3. 出现过两次以上✗✓✗

read() 里那三个分支，就是按这三种状态分的。只有状态 2 的字符才在链表里，所以链表最前面那个就是答案。

为什么需要 repeated 这个 Set

讲义的 Discussion 问：直接用一个没有 size 限制的 LRU 来做这题，对吗？答案是不对。

第一个 a 来 → 加 map + 加链表；第二个 a 来 → 从 map 和链表都删掉。第三个 a 来 → 你分不清它是"第一次来"还是"已经来过又被删了"。

删干净之后，这个字符在数据结构里不留任何痕迹。repeated 就是墓碑，专门记住"这个字符已经废了，以后再来直接无视"。

试试「同一个来四次」那个预设，后两次 a 走的就是 repeated.contains(ch) 那条直接 return 的路。

哨兵怎么用的

构造器里只 new 了一个节点：

tail = new Node(null); tail.next = tail.prev = tail; head = tail;

head 和 tail 都指着它，而它自己的 next 和 prev 都指向自己 —— 一个只有一个元素的循环链表。

好处：remove 里 node.prev 和 node.next 永远不为 null（最差也是哨兵），所以一个 null 判断都不需要。对比 LRU 205 那份答案，那里没用哨兵，remove 里有四个 if。

head 从头到尾没变过，一直是哨兵。所以 head.next 永远是"最早进来且还没重复的那个"，正好是答案。head == tail 表示只剩哨兵，链表空了。
