每个长度，只留最小的那个结尾

tbl[k] = 所有长度为 k 的上升子序列里，结尾最小的那个值。结尾越小越容易接后面的人，所以每个长度只需要留一个代表。tbl 天生严格递增，于是能二分——O(n²) 变 O(n log n) 靠的不是把循环写快，是换了一个有序的状态。

把老师的代码翻译成人话

tbl[k] 到底是什么

不是"第 k 个元素"，是「长度为 k 的上升子序列，最好的那个结尾」。

为什么盯"最小结尾"：同样是长度 4 的上升子序列，结尾是 100 还是 7？当然 7 好——结尾越小，后面越容易接上。所以每个长度只留最优代表，别的都不用记。

result 就是 tbl 里已经用到的最大下标，也就是目前最长的上升子序列长度，最后直接返回它。

find(tbl, 1, result, array[i]) 在找什么

找「最大的那个 j，使得 tbl[j] < array[i]」——也就是「我能接在多长的序列后面」。

找到 j  →  长度 j 的那条序列，结尾比我小，我能接上去
        →  我能凑出长度 j + 1 的序列
        →  所以要写进 tbl[j + 1]

找不到（返回 0）→ 我比 tbl 里所有值都小
                → 只能自己当长度 1 的新代表 → 写 tbl[1]

因为 tbl 严格递增，这个"最大的更小值"能二分，`O(log n)`。这就是 O(n²) 里那层线性内循环被换掉的地方。

两个分支：追加 还是 替换

if (index == result)  tbl[++result] = array[i];   // 追加
else                  tbl[index + 1] = array[i];  // 替换

追加：index == result 说明我比 tbl 里所有值都大，能接在最长那条后面 → 最长长度 +1。

替换：我接不到最长那条，但我能给「长度 index+1」提供一个更小的结尾。长度不变，但这条路以后更好走。

只有"追加"会让答案变大。"替换"一次都不改 result，它是在为将来铺路。切到「全递减」那组看：全程只有替换，`result` 永远是 1。

⚠️ tbl 不是一个真实的子序列

只有 result（长度）是可信的。tbl 里的值可能来自数组的不同位置、顺序甚至对不上。

{3, 4, 1}  →  最后 tbl = [_, 1, 4]
但 1 在 4 的【后面】，[1,4] 根本不是这个数组的子序列
result = 2 是对的（真实答案是 [3,4]）

要真的还原出那条子序列，得另外开一个 parent[] 记前驱。面试常见追问。
