102 · Largest Rectangle Of 1s

拍扁成柱子，一行调一次

把 0/1 矩阵变成高度矩阵——每格记「从我往上数，连续几个 1」。这样每一行就是一排柱子，直接扔给 198 的 largestRectangleInHistogram。M 行调 M 次，取最大。新东西只有「拍扁」这一步。

数据组
0/1 矩阵 matrix
高度矩阵 height（往上数几个 1）

「拍扁」到底在拍什么

一行代码，两种情况

if (matrix[i][j] == 1) {
    height[i][j] = i > 0 ? height[i-1][j] + 1 : 1;
}
// else 不写 —— Java 的 int[][] 默认就是 0

撞到 1：柱子往上接一节 —— 我头顶那格能往上数几个 1（height[i-1][j]），我就比它多一节。第一行头顶没东西，只能是 1。

撞到 0：柱子断了，归 0。这一格站不住人，上面再高也接不下来。

官方代码没写 else height[i][j] = 0，是因为 Java 新建的 int[][] 每格默认就是 0。但如果你改成滚动的一维数组反复复用，这个 else 就必须补上，不然上一行的旧值会漏过来。

为什么拍扁之后就能直接用 198

把第 r 行的高度当成一排柱子。这排柱子里一个「高 h、宽 w」的矩形，翻译回原矩阵就是：

直方图里：第 r 行，高 h，占列 [left, right]
原矩阵里：占行 [r-h+1, r]，占列 [left, right]，全是 1

因为 height[r][j] >= h 的意思就是
「(r,j) 往上连续 h 格全是 1」
—— 这 w 列每一列都能往上撑 h 格，合起来正好一块实心矩形

动图里每次结算，直方图上的橙色矩形和左边 0/1 矩阵里的橙色框是同一个矩形，一个是侧视图，一个是俯视图。

为什么「每行都当底边」不会漏

任何一个全 1 矩形，都有一条最下面的边，假设它落在第 r 行。那么当外层循环走到第 r 行、把这一行当直方图跑的时候，这个矩形一定会被算到。

M 行各当一次底边，就覆盖了所有可能的矩形。所以外层那个 for (int[] heightArray : heights) 不是在"试一试"，是在穷举底边。

复杂度

拍扁      O(M × N)     每格看一眼
每行直方图 O(N)         每个下标进栈一次出栈一次
一共 M 行  O(M × N)

Time  O(M × N)      方阵时写成 O(n²)
Space O(M × N)      height 矩阵本身
                    （只留一维滚动数组可以压到 O(N)）
