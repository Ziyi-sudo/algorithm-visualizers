区间型 dp · 填表顺序

j − i 就是「这段有多长」

所以按 j − i 从小到大填，等价于按区间从短到长算 —— 这就是 DP 那句"小问题先算"。表上看起来是一条斜线一条斜线地往右上推。示例 A = [0, 2, 4, 7, 10]。

按 j − i 分组

三句话说清

① j − i 是什么。dp[i][j] 管的是木头上 A[i] 到 A[j] 这一段。j − i 表示这段里有几个「格子」（相邻切点之间的空隙），也就是切完之后会碎成几块。j − i − 1 就是这段里面要切的刀数。

j − i = 1   →  0 刀   base case，不用切，代价 0
j − i = 2   →  1 刀
j − i = 3   →  2 刀
j − i = 4   →  3 刀   整根木头，就是答案

② 为什么按它增长。dp[i][j] 的公式是 min over k (dp[i][k] + dp[k][j])，其中 i < k < j。两个子段的 j − i 都严格小于原来的（因为 k 被夹在中间）。所以只要"所有更短的都算完了"，当前这格的依赖必然齐全。按 j − i 递增填，就是在保证这一点。

③ 为什么不能按行填。切到第三个 tab 看：按行从左往右走，算到 dp[0][4] 时，它需要 dp[1][4]、dp[2][4]、dp[3][4] —— 那三格在后面的行，还没算。行序保证不了"短的先算"。

for (int len = 2; len < n; len++)        // ← 斜线编号 = j − i
    for (int i = 0; i + len < n; i++) {   // ← 沿着这条斜线滑
        int j = i + len;
        ...
    }

len=2:  (0,2) (1,3) (2,4)
len=3:  (0,3) (1,4)
len=4:  (0,4)              ← 答案

对比一下三类 DP 的「小问题」是什么：

一维线性     小 = 下标小       dp[i] 依赖 dp[i-1]        → 从左往右
二维双序列   小 = 前缀短       dp[i][j] 依赖左上/上/左    → 从上到下、从左往右
区间型       小 = 区间短       dp[i][j] 依赖所有子区间    → 按 j−i 递增，从对角线往外扩

一句话：每类 DP 的填表方向，都是由「谁算小问题」决定的。区间型的"小"是长度，不是下标 —— 所以它的填表方向跟前面几类都不一样。
