一对 [a, b] 拆成两件事

[a, b] 读作「要上 a，得先上 b」。这一对信息要拆开存到两个容器里：graph 记「b 上完之后能解锁谁」，indegree 记「a 还欠几门先修课」。同一条边，两个视角。

依赖图

graph · 谁指向谁

indegree · 还欠几门

为什么下标是反着的

for (int[] p : prerequisites) {
    graph.get(p[1]).add(p[0]);   // p[1] 是先修课 b，往它的列表里塞 a
    indegree[p[0]]++;            // p[0] 是后续课 a，它欠的先修课 +1
}
graph 用 p[1] 当 key 因为 BFS 时我手里拿着的是「刚上完的课」，要问的是「它能解锁谁」。所以列表必须挂在先修课 b 名下。
indegree 用 p[0] 当下标 因为入度的含义是「我还欠几门」。欠先修课的是 a，不是 b。b 反而是被欠的那个。

一句话记：p[1] 是箭头的起点，p[0] 是箭头的终点。graph 挂在起点上（出边列表），indegree 记在终点上（欠债计数）。

方向写反会怎样：如果写成 graph.get(p[0]).add(p[1]) 加 indegree[p[1]]++，整张图会完全颠倒 —— 排出来的顺序是「先上后续课再上先修课」，而且原本无环的图仍然无环，测试不一定报错，只是答案是反的。这是这道题最贵的一处。

示例：n = 4，prerequisites = [[1,0],[2,0],[3,1],[3,2]]
