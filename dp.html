区间 DP 图解

从「吃披萨」那道题出发，把转移为什么跨两步、表怎么填、两端收缩和中心开花的区别画出来。三天后重做这题之前，先看这一页。

01 · 卡点

为什么转移要跨两步

dp[i][j] 的定义里锁死了一个前提：轮到我先手。我拿完之后，那个区间属于朋友，不是 dp——必须等朋友也拿完，才回到同一个前提上。

朋友拿了多少钱，你完全不关心。你只关心他拿的是哪一边——因为那决定了剩给你哪个区间。所以那个 if/else 不是在算钱，是在决定查哪个格子。
02 · 走查

我先手，面对整个数组。两条路各算一遍，取大的——我不需要「知道」该拿哪个。

dp[0][3] = max(102, 5) = 102

04 · 顺序

填表方向由依赖决定

dp[i][j] 依赖 dp[i+2][j]（更大的 i）和 dp[i][j-2]（更小的 j）。你依赖谁，谁就得先算。

写法一 · 逐行
for (int i = n-1; i >= 0; i--)
  for (int j = i; j < n; j++)

i 从大到小、j 从小到大。从表格右下角起，一行一行往上。

写法二 · 按长度
for (int len = 1; len <= n; len++)
  for (int i = 0; i+len-1 < n; i++) {
    int j = i + len - 1;

直接沿对角线推。更能看出「短的先算」这个本质，也是教材里区间 DP 的标准写法。

05 · 分类

两端收缩 vs 中心开花

区间 DP 的状态都是 dp[i][j]，但转移的形状分两大类。你做的这题属于左边那类；「中心开花」是右边那类。

两端收缩中心开花
转移 dp[i][j] ← dp[i+1][j]
            ← dp[i][j-1]
            ← dp[i+1][j-1]		 dp[i][j] = best over k of
  dp[i][k-1] + dp[k+1][j] + cost(k)
循环两层（i, j）三层（i, j, k）
复杂度O(n²)O(n³)
典型题 吃披萨（这题）
最长回文子序列
石子游戏 / 预测赢家		 戳气球 Burst Balloons
矩阵链乘法
合并石子 / 石子归并
思考角度 「这一步从哪端拿？」 「区间里最后处理的是谁？」
中心开花的关键思路是「倒着想」。戳气球那题正着想（先戳谁）会让两边互相影响，切不干净；反过来问「最后被戳破的是哪个」，那一个左右两边就彻底独立了，才能拆成两个子区间。
你这题不用这套——因为披萨只能从两端拿，天然就是收缩型。
06 · 识别

什么时候该想到区间 DP

信号 1

状态天然是一段连续区间

剩下的东西永远是原数组的一个连续片段，不会散成好几块。

信号 2

操作发生在两端，或者需要挑中间一个点

从两头拿 → 收缩型。在中间选一个「最后处理的」→ 开花型。

信号 3

大区间的答案能由小区间拼出来

而且 n 通常不大（几百以内），因为复杂度是 O(n²) 或 O(n³)。

面试里说出来就是：This is an interval DP — the state is a contiguous range, and I build longer ranges from shorter ones.

这题难，不是错觉：区间 DP + 对手动作确定 + 转移跨两步，三个东西叠在一起。你独立做到的部分——圈出 always 那句、从 example 推出谁先手、自己推出转移——是这题真正的难点。卡住的是「怎么落成代码」，那是另一回事。
