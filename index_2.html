ALG Round 3 · Execution Order

面试 45 分钟执行顺序

什么时候说、什么时候闭嘴、每一段说什么。沉默不是问题，没被标注的沉默才是。三段合法沉默都有各自的开场句，全在下面。

出声 沉默（已标注）
0:00 8:00 25:00 45:00

合法沉默只有 18 分钟，其中 17 分钟是写代码。也就是说：前 8 分钟你几乎一直在说话，而那 8 分钟决定了这场面试的评分上限。

第一段 · 开局 8 分钟

0:00

申请沉默说

拿到题的第一个动作是开口，但不是开始分析——是给自己买 90 秒。

Let me read through this once — I'll be quiet for a minute or two.

没有这句，接下来的沉默在他眼里是「卡住了」；有了这句，同样的沉默是「在读题」。一句话的成本，改变整段的性质。

0:15

默读 · 圈限定词沉默

圈出所有限定词：strictly / any / at most / distinct / subarray / positive。看不懂的打 ?，不查、不停。

题面超过三屏就中途冒一句 “Still reading — there's a lot of setup here.” 让他知道你没死机。

1:45

复述题目说

用自己的话，不是念题。20 秒。

So, to make sure I understand — we're given an array of points, and we need to return the size of the largest subset where every pair forms a line with positive slope.

这一步排在提问前面，不能换。复述会当场暴露你读反了哪个限定词——他会打断你纠正，这是白捡的一次免费校验。而且它给了你 20 秒去组织问题；直接开始问，你问的往往是最先想到的那种废问题。

2:15

澄清提问 ×3说

只问会改变代码的问题。一个都不问，评分表上那一栏直接空着。

Can the input contain duplicate points, or two points with the same x? Roughly how large is the input? That'll tell me whether O(n²) is acceptable. Just to confirm the return value — if there's no valid pair at all, I return 0, not 1?

这三个各自对应代码里一处真实分支：垂直线处理、复杂度选型、最后一行。像「数组会是 null 吗」这种不影响代码的，他看得出你在凑数。

3:30

推约束 → 归约说

这是全场最值钱的 150 秒。推导和断言在评分上是两档：直接说「这是 LIS」，他不知道你是懂了还是背过。

The slope is (y₂−y₁)/(x₂−x₁). For that to be positive, first the denominator can't be zero — otherwise it's a vertical line and the slope is undefined. Second, numerator and denominator need the same sign — so if x₂ > x₁, then y₂ > y₁, strictly. Strict inequality is transitive, so if consecutive pairs increase, every pair does. So this reduces to the longest strictly increasing subsequence of the y-values.

口语提醒：strictly / distinct / transitive 要重读。这是你和只会背模版的人之间最短的区分信号。模型名要说全——“the longest subsequence” 不算数，最长子序列就是整个数组。

6:00

Edge case + 复杂度 + 递球说

主动踩坑，别等他挖。而且要给具体例子——只说「edge case 是返回 0」很虚。

Before I code — one edge case: for three points on a horizontal line, like (0,0), (1,0), (2,0), the answer is 0, not 1 and not 3. I'll start with the O(n²) DP — it's easier to get right and handles the same-x case cleanly. Does that work for you?

递球是同步，不是示弱。被叫停反而是赚的——省得写完 20 行才发现方向不对。而且这个具体例子等下测试环节能直接复用。

8:00

写代码沉默为主

最长的一段合法沉默，前提是方向已经同步且他点过头。方向没同步就闷头写，那不是沉默，是失联。

不是静音，也不是逐行解说：每 3–5 分钟一句，只说意图不念语法。

I'm handling the duplicate case here. This is just the guard for the empty input. Let me come back to this edge case in a second.

❌ “for int i equals zero, i less than n” → 流水账，显得你只会敲键盘
✅ “for each point, I look back at everything before it” → 决策依据
他也是程序员，代码他看得懂；他让你讲是想看思维清晰度。

25:00

Walkthrough + 测试说

写完主动开口，别等他说「试试这个」。这段分数和写代码一样重，也是最多人省略的一段。

Let me walk through an example to verify. [(0,0),(1,0),(2,0)] — y is [0,0,0], no strict increase, so LIS is 1, and since that's less than 2, we return 0. ✓ That's the edge case I mentioned.

四个例子就够，但要各对应一条你前面 flag 过的：一个正常通过、一个触发 return 0、一个触发同 x、一个空/单元素。形成闭环，他会觉得你很有条理。

33:00

Follow-up + 反问说

答不出细节没关系——能说出方向就拿到分了。最后一定要留问题问他。

That would turn it into a 3D dominance problem — sort away one dimension, then a BIT on the other two. I have the O(n²) working. Given the time, should I optimize, or walk through more cases?

最后那句把优先级交给他——他知道评分表上还缺什么，你不知道。

沉默的两种性质

合法 · 都有开场句

  • 读题（~90 秒）Let me read through this once.
  • 中途想（≤20 秒一段）Let me think for a second — I want to get the boundary right.
  • 写代码（最长）前提是方向已经讲完并被认可，否则不合法。

要命 · 每一秒都在扣分

  • 他刚问完你的沉默Good question, let me think about that.
  • 偷偷改 bug 的沉默Actually, wait — that doesn't handle the same-x case.
  • 卡住瞪屏幕I'm not seeing the optimal approach yet — let me start with brute force.

卡住时的保命句

需要想一下
Let me think about this for a second — I want to make sure I get the boundary right.
某个词卡住了
…the thing that keeps track of — sorry, the auxiliary array.
发现自己错了
Actually, wait — that doesn't handle the same-x case. Let me fix that.
完全没头绪
Let me start with brute force and look for the redundant work.
需要提示
I'm considering two directions — sorting first, or a graph formulation. Does one seem more promising?
时间快到了
Given the time, should I optimize, or walk through more test cases?

面试之外 · 每题 60 秒

45 SEC出声 · 录音只讲 1:45–8:00 那一段的四个点：Return → Constraint → Reduction → Edge case。卡壳不停下来查。
15 SEC写两行❌ 死因：半句话，具体到误判。
💬 金句：≤15 词，是句式不是台词。
DAILY听 1–2 段挑当时就觉得讲得最烂的那道。只找填充词、中译英的停顿、磕巴的词。每题都听，两天就放弃。
WEEKLY连读金句出声读三遍。目标是 reduces to / transitive / guaranteed that 变成条件反射。平时不回看。
