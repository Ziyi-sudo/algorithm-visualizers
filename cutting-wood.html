补两端，然后枚举第一刀

木头长 10，必须在 2, 4, 7 处切开。每切一刀的代价 = 当前这段木头的长度，所以顺序会影响总价。难点不在公式，在于把「木头的位置」换成「切点的下标」。

木头 · 红线是必须切的位置，蓝线是补上的两端

helper 数组 A（补两端后）

枚举第一刀切在哪个 k

dp 表 · dp[i][j] = 切开 A[i] 和 A[j] 之间所有点的最小代价

五个要点

格内容
物理意义dp[i][j] = 把 A[i] 到 A[j] 这一段木头，切开中间所有切点，所需的最小总代价
表大小int[n][n]，n = cuts.length + 2。不开 padding，i/j 都是 A 上的下标，只用 i < j 的右上三角
base casej - i <= 1 → dp[i][j] = 0　中间没有切点，不用切。Java 默认值就是 0，不用手写
inductiondp[i][j] = min over k (dp[i][k] + dp[k][j]) + (A[j] - A[i])，i < k < j
resultdp[0][n-1]　整根木头

① 「补两端」是全题的钥匙。你卡在定义不出 dp，根因是想用「木头的位置/长度」当下标 —— 那样下标空间是 L（可能很大），而且区间端点跟切点对不齐。把 0 和 L 补进 cuts 数组之后，任意一段木头都能用 A 上的两个下标表示，一段的长度就是 A[j] - A[i]。

② A[j] - A[i] 为什么能提到 min 外面。不管你先切哪个 k，这一刀都是在整段 [i,j] 上切的，代价固定等于整段长度，跟 k 无关。所以 min 里只需要比较两个子段的代价。

③ 为什么 dp[i][k] + dp[k][j] 不重不漏。切完 k 这一刀，左右两段就彻底独立了，互不影响 —— 这是"切割型"区间 DP 成立的前提。

④ 填表顺序。dp[i][j] 依赖 dp[i][k] 和 dp[k][j]，其中 i < k < j —— 都是更短的区间。所以按区间跨度从小到大填：

for (int len = 2; len < n; len++)          // 跨度，从 2 开始（跨度 1 是 base）
    for (int i = 0; i + len < n; i++) {
        int j = i + len;
        int best = Integer.MAX_VALUE;
        for (int k = i + 1; k < j; k++)      // 枚举第一刀
            best = Math.min(best, dp[i][k] + dp[k][j]);
        dp[i][j] = best + (A[j] - A[i]);
    }
return dp[0][n - 1];

老师那版是等价的另一种写法：外层 i 从 1 递增当作右端点、内层 j 从 i-1 倒着走当作左端点，用 minCost[j][i]（j 小 i 大）。本质都是「行从下往上、列从左往右、从对角线开始」，只是命名相反。老师标的 TC 是 O(n²)，实际是 O(n³)（多了枚举 k 那层）。

⑤ 跟前面几类 DP 的差别 —— 多了一层枚举。

类型dp 下标是什么依赖谁填表方向TC
一维线性一个位置 / 长度dp[i-1] 或 dp[0..i-1]从左往右O(n) / O(n²)
二维双序列两个串各自的进度左上 / 上 / 左从上到下、从左往右O(mn)
区间型同一数组上的一段范围所有更短的子区间从对角线往外扩O(n³)

为什么区间型要从对角线开始：在这张表上，「离对角线的距离」就是「区间长度」。对角线是长度最小的区间，DP 铁律是小问题先算 —— 所以从对角线出发，一圈圈往右上方扩，这就是"中心开花"。
