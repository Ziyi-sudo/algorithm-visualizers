01 · 开场

澄清提问

P1

先问，别先写

0:00–2:00

"Before I start — a few quick questions."

"Can the input contain duplicate points, or two points with the same x?"

"Roughly how large is the input? That'll tell me whether an O(n²) solution is acceptable or I should aim for O(n log n)."

"And just to confirm the return value — if there's only one point, or no valid pair at all, I return 0, not 1. Is that right?"

为什么

Google 明确考察 problem clarification。一个问题都不问，评分表上那一栏直接空着。

这三个问题不是随便挑的，每个都会真的改变代码：

  • 同 x 的点 → 决定要不要处理垂直线
  • 输入规模 → 决定 O(n²) 够不够
  • 返回 0 还是 1 → 决定最后一行

别问那种不影响代码的问题（"数组会是 null 吗"），面试官看得出来你在凑数。

02 · 核心

推导约束

P2

复述 + 把条件推成不等式

2:00–4:00

"So we're given an array of points with integer coordinates, and we want the size of the largest subset where every pair of points forms a line with positive slope."

"Let me work out what 'positive slope' actually constrains. For two points, the slope is (y₂−y₁)/(x₂−x₁). For that to be positive, two things have to hold."

"First, the denominator can't be zero — so no two points in the set can share the same x. Otherwise it's a vertical line and the slope is undefined."

"Second, numerator and denominator have to have the same sign. So if I order the pair with x₂ > x₁, then y₂ > y₁ — strictly."

"So the condition on the whole set is: both x and y are strictly increasing."

为什么

「推导」和「断言」在评分上是两档。直接说"这题就是 LIS"——面试官不知道你是懂了还是背过。

把 (y₂−y₁)/(x₂−x₁) > 0 拆成"分母非零"+"同号"两步，是在展示你能从定义出发。

「分母不能为零」这一步是分水岭。大多数人跳过它，然后代码里漏掉同 x 的情况。你说出来了，面试官会记一笔。

口语提醒：strictly 要重读。它是这题唯一区分 < 和 <= 的词。

整数那条也顺口提一句 "Since the coordinates are all integers, I'd avoid floating-point division entirely — I can compare with cross multiplication instead."
面试官爱听这种数值稳健性的细节，一句话的成本，加分。
03 · 最关键的一段

归约到 LIS

P3

为什么「任意两点」可以变成「排好序后递增」

4:00–6:00

"Now here's the part I want to be careful about. The condition is on every pair, which sounds like it needs O(k²) checking. But strict inequality is transitive."

"So if I sort a candidate set by x, and each consecutive pair has increasing x and increasing y, then by transitivity every pair does. The pairwise condition collapses into a condition on the sorted order."

"That means: sort all the points by x, and the problem becomes finding the longest strictly increasing subsequence of the y-values."

"So this reduces to LIS — the longest strictly increasing subsequence."

这段是全场最值钱的 60 秒

传递性论证是把「every pair」变成「LIS」的唯一桥梁。没有这一步，归约就是猜的。

Google 面试官很可能就在这里追问一句 "Why is checking consecutive pairs enough?" —— 你已经答过了，他会直接跳过。

说出模型名字，说全。"the longest subsequence" 不算——最长子序列就是整个数组。必须是 longest strictly increasing subsequence。

reduces to 这个动词比 "this is basically" 专业一个档次。

04 · 边界

写码前主动过 edge case

P4

把坑先说出来

6:00–7:00

"Before I code, let me flag the edge cases."

"A single point is always trivially a valid set of size 1, since there's no pair to check. So the DP will never return 0 on its own — the minimum it can produce is 1."

"But the problem says: if no pair has positive slope, return 0. So at the very end, if my answer is less than 2, I return 0."

"Concretely — for three points all on a horizontal line, like (0,0), (1,0), (2,0), every slope is zero, so the answer is 0, not 1 and not 3."

为什么

主动踩坑，别等面试官挖。他心里的评分是"这人自己发现了"，而不是"我提示了他才反应过来"。

而且要给具体例子。只说"edge case 是返回 0"很虚；给出 (0,0),(1,0),(2,0) 才证明你真的想过。

这个具体例子等下测试环节还能直接复用，一举两得。

05 · 方案

给两个方案，让面试官选

P5

先报复杂度，再动手

7:00–8:00

"There are two standard ways to do LIS."

"The straightforward one is O(n²) DP: dp[i] is the size of the best valid set ending at point i. For each i, I look back at every j, and if point j has a smaller x and a smaller y, I can extend."

"The optimal one is O(n log n) using a tails array and binary search."

"I'll start with the O(n²) — it's easier to get right, and it handles the same-x case very cleanly. Then I can optimize if we have time. Does that work for you?"

为什么

先报复杂度再写代码，是在证明你知道自己在选什么，而不是只会一种。

"Does that work for you?" 是同步，不是示弱。被叫停反而是赚——省得写完 20 行才发现方向不对。

先写 O(n²) 是对的策略：能跑的次优解 > 写崩的最优解。而且这题的 O(n²) 写法反而更稳（见下）。

06 · 写码

两版代码

P6a

O(n²) DP — 主推

8:00–20:00

"I'll sort by x first, then run the DP."

"Each dp[i] starts at 1, because a single point is always valid on its own."

"The inner check is the important line: both x[j] < x[i] and y[j] < y[i]. The x check is what kills the vertical-line case — two points with the same x can never chain."

"And the last line converts a lone 1 into 0."

边写边说的正确粒度

只讲意图，不念语法。

✗ "for int i equals zero, i less than n, i plus plus"

✓ "for each point, I look back at everything before it"

那行 && 值得专门停下来说一句——它是这题唯一一个非显然的地方。指出来，等于告诉面试官你知道坑在哪。

Java · O(n²) time, O(n) space
import java.util.Arrays;

public class Solution {
  public int largest(Point[] points) {
    int n = points.length;
    if (n <= 1) return 0;

    Point[] arr = points.clone();
    Arrays.sort(arr, (a, b) -> Integer.compare(a.x, b.x));

    int[] dp = new int[n];
    int gMax = 0;

    for (int i = 0; i < n; i++) {
      dp[i] = 1;                        // 单点自成一个合法集合
      for (int j = 0; j < i; j++) {
        if (arr[j].x < arr[i].x         // ← 挡掉同 x（垂直线）
         && arr[j].y < arr[i].y) {      // ← 严格递增
          dp[i] = Math.max(dp[i], dp[j] + 1);
        }
      }
      gMax = Math.max(gMax, dp[i]);
    }
    return gMax < 2 ? 0 : gMax;         // ← Note 那条边界
  }
}
P6b

O(n log n) — 如果还有时间

追加

"For the O(n log n) version there's a subtlety I want to call out."

"The binary-search version only looks at the y-values, so it loses the x information. If two points share an x and I sort their y ascending, the algorithm would happily chain them — which is wrong."

"The fix is in the comparator: when x ties, sort y descending. Then two points with the same x appear in decreasing y order, so a strictly increasing subsequence can never pick both."

"It's a neat trick — the sort itself makes the illegal combinations unreachable."

这一段是加分项，不是必需项

能主动说出这个 tie-break，说明你真的推过，不是背的模板。

我用随机数据对拍过 3000 组：
tie 用 y 升序 → 751 组答案错误
tie 用 y 降序 → 0 组错误

反例：[(0,3),(3,0),(1,0),(1,2)] → y 数组 [3,0,2,0] → LIS = 2，选中 (1,0) 和 (1,2)，同一个 x。正确答案是 0。

Java · O(n log n) time, O(n) space
import java.util.Arrays;

public class Solution {
  public int largest(Point[] points) {
    int n = points.length;
    if (n <= 1) return 0;

    Point[] arr = points.clone();
    // x 升序；x 相同时 y 降序 —— 让同 x 的点无法进同一条严格递增链
    Arrays.sort(arr, (a, b) -> a.x != b.x
        ? Integer.compare(a.x, b.x)
        : Integer.compare(b.y, a.y));

    int[] tails = new int[n];
    int len = 0;
    for (Point p : arr) {
      int i = lowerBound(tails, len, p.y);   // 第一个 >= p.y 的位置
      tails[i] = p.y;
      if (i == len) len++;
    }
    return len < 2 ? 0 : len;
  }

  private int lowerBound(int[] a, int len, int target) {
    int lo = 0, hi = len;
    while (lo < hi) {
      int mid = lo + (hi - lo) / 2;
      if (a[mid] < target) lo = mid + 1;
      else hi = mid;
    }
    return lo;
  }
}
07 · 测试

主动跑例子

P7

不要等面试官说「试试这个」

25:00–33:00

"Let me trace through a few cases."

"[(0,0),(1,1),(2,2)] — sorted by x, y is [0,1,2], strictly increasing, so LIS is 3. Answer 3. ✓"

"[(0,0),(1,0),(2,0)] — y is [0,0,0], no strict increase, so LIS is 1, and since that's less than 2, we return 0. ✓ That's the edge case I mentioned."

"[(1,0),(1,5)] — same x. The x check in the inner loop fails, so neither extends the other. LIS is 1, we return 0. ✓"

"Empty array or a single point — caught by the guard at the top."

为什么

测试环节的分数和写代码一样重，而且是最多人省略的一段。

四个例子的选择是有讲究的：

  • 一个正常通过的
  • 一个触发 return 0 的
  • 一个触发同 x 的
  • 一个空/单元素

每一个都对应你前面 flag 过的一条。形成闭环，面试官会觉得你很有条理。

08 · 追问准备

面试官大概率会问的四个

"What if we allowed non-negative slope instead — so horizontal lines are okay?"
别急着说"把 < 改成 <= 就行"，这是陷阱。 斜率 ≥ 0 仍然要求 x 互不相同（垂直线依然非法），但 y 变成非严格递增。此时那个 tie-break 技巧不再够用——同 x 且 y 相等的两个点，在非降子序列里会被同时选中。

正确做法是按 x 分组处理：同一个 x 的所有点，都拿"进入这一组之前"的状态来更新，组内互相看不见。

（我对拍验证过：只靠 tie-break 在 4000 组里错了 858 组；分组处理 0 组错误。）
"Can you return the actual set of points, not just the size?"
在 O(n²) DP 里加一个 prev[] 数组记录每个 dp[i] 是从哪个 j 转移来的，最后从 argmax(dp) 一路回溯即可，额外 O(n) 空间。

顺带说一句这也是选 O(n²) 的理由之一——O(n log n) 的 tails 版本要还原具体序列会麻烦得多。这句话会让面试官觉得你的方案选择是有考量的。
"What if the coordinates could be very large? Any overflow concerns?"
排序 comparator 里不要写 a.x - b.x——两个极端 int 相减会溢出，比较结果反号，排序直接乱掉。用 Integer.compare(a.x, b.x)。

交叉相乘 (y₂−y₁)*(x₂−x₁) 也可能溢出 int，必要时转 long。

这题的解法本身不做乘法，所以其实不受影响——但能主动指出来，说明你有这根弦。
"What if it were 3D — every pair has to increase in all three coordinates?"
这就从「最长递增子序列」变成了三维偏序 / 最长链问题。第一维排序降掉，剩下两维用树状数组或 CDQ 分治处理，做到 O(n log²n)。

答不出细节没关系——能说出"这变成了三维偏序"并给出方向，就已经拿到这一问的分了。面试官问这个通常不指望你写出来。
09 · 保命

卡住的时候说什么

沉默是面试里最贵的东西。卡住不可怕，安静地卡住才可怕——面试官看不到你的思路，只能记「无进展」。

需要想一下
"Let me think about this for a second — I want to make sure I get the boundary right."
给自己 10 秒，而且说明了你在想什么。
词卡住了
"...the thing that keeps track of — sorry, the auxiliary array."
描述它，别停下来。绕过去比卡住强十倍。
发现自己错了
"Actually, wait — that doesn't handle the same-x case. Let me fix that."
自己抓到 bug 是加分，不是扣分。大方改，别掩饰。
完全没头绪
"I'm not seeing the optimal approach yet. Let me start with brute force and look for the redundant work."
永远有下一步可走。暴力解也是解。
需要提示
"I'm considering two directions — sorting first, or a graph formulation. Does one of those seem more promising to you?"
这样要提示不丢分，因为你展示了两个候选方向。
时间快到了
"I have the O(n²) working. Given the time, should I optimize, or walk through more test cases?"
把优先级交给面试官，他知道评分表上还缺什么。
10 · 跟读版

连读全文

去掉批注的连续版本，用来跟读。看着念三遍 → 只看加粗词说一遍 → 全盖住说一遍。走到哪步算哪步。

"Before I start — can the input contain duplicate points, or two points with the same x? And roughly how large is the input? That'll tell me whether O(n²) is acceptable. Also, just to confirm: if there's no valid pair at all, I return 0, not 1?"

"Okay. So we're given an array of points with integer coordinates, and we want the size of the largest subset where every pair forms a line with positive slope."

"Let me work out what that constrains. The slope is (y₂−y₁)/(x₂−x₁). For it to be positive, first the denominator can't be zero — so no two points can share the same x, otherwise it's a vertical line and the slope is undefined. Second, numerator and denominator need the same sign — so if x₂ > x₁, then y₂ > y₁, strictly. So the set has to be strictly increasing in both x and y."

"Since the coordinates are all integers, I'd avoid floating-point division and use cross multiplication if I needed to compare slopes at all."

"Now, the condition is on every pair, which sounds like O(k²) checking. But strict inequality is transitive — so if I sort a candidate set by x and each consecutive pair increases in both coordinates, then every pair does. The pairwise condition collapses into a condition on the sorted order."

"So: sort all the points by x, and this reduces to the longest strictly increasing subsequence of the y-values."

"Before I code, one edge case. A single point is always trivially valid, so the DP never returns 0 on its own — the minimum it produces is 1. But the problem wants 0 when no pair works. So at the end, if the answer is less than 2, I return 0. Concretely, for (0,0), (1,0), (2,0) — all on a horizontal line — the answer is 0, not 1 and not 3."

"There are two standard ways to do LIS. The straightforward one is O(n²) DP: dp[i] is the best valid set ending at point i, and for each i I look back at every j — if point j has a smaller x and a smaller y, I can extend. The optimal one is O(n log n) with a tails array and binary search."

"I'll start with the O(n²) — it's easier to get right, it handles the same-x case cleanly, and it makes reconstructing the actual set easy if you want that later. Then I can optimize if we have time. Does that work for you?"

"Let me trace through a few cases. [(0,0),(1,1),(2,2)] gives y-values [0,1,2], strictly increasing, so 3. [(0,0),(1,0),(2,0)] gives [0,0,0], LIS is 1, less than 2, so we return 0. 11 · 速查

这道题的评分要点
