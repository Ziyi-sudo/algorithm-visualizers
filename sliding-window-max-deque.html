答案

你问的三件事

一、为什么存下标，不存值

因为要判断「过期」，而过期是位置的概念——某个人滑出窗口了。值本身不带位置：队列里躺着一个 4，它自己不知道它是第几个，也就没法判断该不该走。

下标则两样都有：位置直接可读，值 array[idx] 一步就取到。下标能推出值，值推不出下标——存下标信息不丢，存值是有损的。

678 Next Greater Number 那题存值是特例（无重复 + 全程不关心位置）。这题两个条件都不成立，只能存下标。

二、peekFirst() <= i - k 这个不等式是怎么来的

先把窗口写成下标区间。以 i 结尾、长度 k 的窗口，左端是 i-k+1：

窗口 = [i-k+1, i]      两端都含，正好 k 个

还在窗口内   ⇔  idx >= i-k+1
已经过期     ⇔  idx <= i-k          ← 上一行取反

验算 i=3, k=3：窗口 = [1, 3]，过期线 i-k = 0
              → 下标 0 出局，下标 1、2、3 留下   ✓

为什么只用 if 就够（很多标准写法是 if）：每一步 i 只前进 1，窗口只往右挪一格，所以最多只有一个人过期。写 while 也对，只是循环体最多执行一次。

三、为什么 i >= k - 1 才开始收答案

第一个完整窗口是 [0, k-1]，它的右端下标就是 k-1。所以 i 走到 k-1 那一刻，窗口才第一次凑满 k 个元素。

i = 0 .. k-2   窗口还没凑够 k 个 → 不收
i = k-1        第一个完整窗口 [0, k-1] → 收第 1 个答案
i = n-1        最后一个窗口 [n-k, n-1] → 收第 n-k+1 个答案

答案个数 = n - k + 1

这一步排在 ②③ 之后，不是随便排的：array[i] 必须先进队，因为它自己就可能是当前窗口的最大值。

补充：① 和 ② 各自在防什么

② 管队列的「质量」——踢掉又小又老的，保证从头到尾严格递减，所以队头一定是队列里最大的。

① 管队列的「长度」——踢掉滑出窗口的，保证队列里的人全都还在窗口内。少了它，队头可能是个早就出界的旧最大值，答案直接错；同时队列会一路涨到 O(n)，而不是 O(k)。

两条合起来才推得出「队头 = 当前窗口最大值」。切到严格递减那组数据看得最清楚：② 一次都不触发（新人永远最小），全靠 ① 撑着。
