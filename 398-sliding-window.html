三个最容易写错的地方

① 判断用的是「更新前」的 count，不是更新后的。

map.put(tmp, count - 1); if (count == 1) match++; —— count 是减之前的值。进的时候 1→0 才叫「刚配平」，出的时候 0→1 才叫「刚失配」。

0→−1 和 −1→0 都不动 match。只有跨越 0 这条线的那一刻才动。

② map 里的值可以是负数。窗口里某个字符多了，计数就变成负的。

这在 O(n·k) 那版里是非法状态（一发现 0 就 return false），滑窗版允许超标 —— 因为它知道多出来的迟早会从左边滑出去。

这就是「检查」和「维护」的区别：检查只看当前窗口，维护跨窗口连续。

③ 两个边界都是「个数 ↔ 位置」的换算。

i >= s.length() 才开始移出 —— 前 k 个字符是在攒窗口，攒满了才有东西可移。

i - s.length() + 1 是窗口左端下标，也就是要记录的起点。i 是右端。

match 这个计数器值多少钱

它把「扫一遍 k 个字符确认全为 0」这个 O(k) 的判断，压缩成一次 O(1) 的整数比较。

match = 有多少个不同字符的需求量正好是 0。当 match == map.size()，所有字符都配平，就是一个 anagram。

这是整道题最值钱的设计。没有它，滑窗也还是 O(n·k)。
