回答三个疑问

「是填完表再扫一遍找最大值吗？」 —— 不用。longest 和 start 是边填边更新的：每算出一个 common[i][j]，立刻跟 longest 比一下。填完表答案就已经在手里了。这跟一维 DP 里维护 globalMax 是同一个动作。

「为什么 start = i - longest + 1？」 —— longest 是这段公共子串的长度，i 是它在 s 里的结尾下标。结尾往回数 longest 个字符，起点就是 i - longest + 1。最后 s.substring(start, start + longest) 取出来。

「我一开始想的是 two pointer / sliding window，为什么不行？」

sliding window 的前提 窗口在一个序列上滑动，靠"扩右边界 / 缩左边界"维护一个可增量更新的性质。它要求答案有单调性 —— 窗口变大时性质单调变差。
这题为什么不满足 有两个独立的字符串，s 上的位置和 t 上的位置可以任意配对，不存在"一个窗口"。而且 s 往右挪一格，跟 t 的匹配关系可能完全重来 —— 没有单调性可利用。

识别信号：两个序列之间找关系 ⇒ 二维 DP，M[i][j] 表示「s 的前 i 个 vs t 的前 j 个」。讲义原话：「Two Strings 寻找 Minimum Edit Distance / Longest Common Substring / Subsequence，一般解题方法都是 S1 的前 i 个 letter 和 S2 的前 j 个 letter 比较，induction rule 一般要看 M[i][j] 和 M[i-1][j]、M[i][j-1]、M[i-1][j-1] 之间关系。」

Substring 只看一个大哥，Subsequence 看三个：

Substring（要连续）
    s[i] == t[j]  →  common[i][j] = common[i-1][j-1] + 1     ← 只有对角线
    s[i] != t[j]  →  common[i][j] = 0                        ← 断了就归零
    result: 边填边记的 longest

Subsequence（不要连续）
    s[i] == t[j]  →  dp[i][j] = dp[i-1][j-1] + 1
    s[i] != t[j]  →  dp[i][j] = max(dp[i-1][j], dp[i][j-1])  ← 断了还能继承
    result: dp[m][n]（右下角）

差别只有"不相等时怎么办"这一行：归零 vs 继承。
这跟一维的 Subarray vs Subsequence 是完全平行的对照。

复杂度：Time O(s·t)，Space O(s·t)。因为只看左上角，空间可以优化到一行（滚动数组）。
