刷题英语五遍法

给已经会写代码、但被英文题面拖慢的人。核心只有一句：先自己建模，再回头校验，最后才开口讲。

00

顺序才是关键，不是模版

速读模版本身没问题，问题在于它被放在了什么位置。下面五步的先后顺序是不能换的。

Pass 1
限时速读建模
3 min · 计时
Pass 2
精读校验
5 min · 不计时
Pass 3
写代码
正常节奏
Pass 4
英文口述
3 min · 出声
Pass 5
复盘两栏
2 min

为什么精读一定在口述之前：口述是「固化」动作。你把一个理解讲出口，它就被写进肌肉记忆了。没校验就开讲，等于在熟练地背错的东西。反过来，精读还是口述的弹药库——题面里现成的 strictly increasing、in ascending order、it is guaranteed that，正是你讲题该用的词。从题面偷表达，比背话术模版有效得多，因为是真语料，而且当场就用得上。

限时速读建模

禁止查词
  • 只填下面那四个格子（Goal / Logic / Traps / DS）。
  • 看不懂的词猜过去，但必须在旁边打一个 ?。

目的：模拟考场压力，并且——更重要的——逼你产生一个可以被证伪的预测。没有预测，后面的精读就没有对比信号，学习效率会掉一大半。

精读校验

这一遍才是学习发生的地方

注意：这不是逐字翻译，也不是抄生词本。是验证——只看你刚才猜过去的地方猜对没有。猜对了就跳过，猜错了才记。

02

Pass 1 的四个格子

草稿纸上画四格，只填关键词，不写句子。

Goal
我要返回什么？

直接找 Return / Find / Output，对照方法签名验证类型。

Return int (size) of largest subset
Logic
条件转成什么不等式？

把英文条件翻成数学式，再映射到算法模型。背景故事全部忽略。

positive slope ⇒ x↑ AND y↑ (strict)
+ x₁ ≠ x₂
→ LIS on y, after sort by x
Traps
哪里会 WA？

扫 Note / Assumptions / Constraints 和所有括号。专找否定词和极限词。

1. positive = >0，横线不算
2. 无合法 pair 时 return 0 而非 1
3. x 相同 = 垂直线 = 非法
DS
用什么装？复杂度？

由 Logic 反推工具，顺手写下目标复杂度。

Point[] → sort O(n log n)
→ tails + binarySearch O(n log n)
03

必须条件反射的 30 个逻辑词

实义词不用背，这张表必须背——因为这些词直接决定你代码里写 < 还是 <=。速读时看到就圈出来。

看到 → 立刻转成 → 写错的代价
英文转成写错会怎样
量词 · 全称还是存在
for any / such that any∀ 全部读成「存在」→ 整道题模型错
there exists / some∃ 存在一个读成「全部」→ 条件过强，答案偏小
at least k≥ k边界差 1
at most k≤ k（可以是 0）漏掉「一个都没有」的情况
exactly k== k写成 ≥ 会多收答案
no more than k≤ k同 at most
单调性 · 严格还是不严格
strictly increasinga[i] < a[i+1]写成 ≤ → 允许了相等，答案偏大
non-decreasinga[i] ≤ a[i+1]写成 < → 答案偏小
non-increasinga[i] ≥ a[i+1]同上，方向相反
ascending / descending order升序 / 降序排序方向搞反
monotonic单调（方向不限）只判了一个方向
连续性 · 这一组最容易混
subarray / substring连续当成子序列 → 模型完全跑偏
subsequence不要求连续当成连续 → 答案偏小
contiguous下标连续同 subarray
consecutive数值连续（3,4,5）和 contiguous 混淆
adjacent相邻两个范围扩大到任意两个
唯一性 · 重复怎么办
distinct两两不同漏去重
may contain duplicates可能有重复少一组 case，二分模板要改
with repetition allowed元素可重复使用背包 / 组合的 for 循环方向写反
0-indexed / 1-indexed下标起点全体答案偏移 1

数值范围 · 零算不算
positive> 0（不含 0）把 0 收进来 → 本页那道题的坑
non-negative≥ 0（含 0）把 0 排除 → 少答案
inclusive闭区间 [a, b]端点漏算
exclusive开区间，不含端点端点多算

操作与前提 · 决定要不要写防御代码
in place原地改，不开新数组空间复杂度不达标，面试直接扣分
O(1) extra space额外空间常数同上
it is guaranteed that ...保证成立，不用判断写了没必要的校验，浪费时间
you may assume ...可以假设，不用校验同上
if no such ..., return -1找不到的返回值默认返回 0，全盘皆错
04

Pass 4 讲题：要骨架，不要台词

面试官一听就能分辨背稿和真懂——背稿的人语速平、重音怪、一被追问就崩。所以固定下来的应该是五个 move 的顺序，句子每题现编，材料从题面里拿。

M1
复述题目，确认你听懂了
"So, to make sure I understand — we're given ... and we need to return ..."
用你自己的话，不是逐字念题。这一步 20 秒够了。
M2
把关键约束说成不等式，重音落在限定词上
"The key constraint is ... which means x has to be strictly increasing, and the x-values must be distinct."
strictly / distinct / at most 这类词要读重。这是你和只会背模版的人之间最短的区分信号。
M3
归约，并且叫出模型名字
"So this reduces to finding the longest strictly increasing subsequence of ..."
this reduces to 是这一步的高价值动词，比 "this is basically" 专业得多。
M4
写码前主动过 edge case
"Before I code — one edge case: if no valid pair exists, we return 0, not 1. And ties in x need special handling, otherwise ..."
主动提，别等面试官挖。这是整套流程里性价比最高的 30 秒。
M5
给复杂度，然后把球递回去
"That's O(n log n) time, O(n) space. Does that sound reasonable before I start coding?"
递球是为了同步，不是为了「控场」。真被叫停反而是好事——省得你写完一整版才发现方向不对。
05

实战：Largest Set Of Points With Positive Slope

这题的题面英语藏了三个坑，而且第三个坑会让一份看起来完全正确的解法挂掉。

题面里的三处原文，各对应一个坑

原文坑在哪
any pair of points 这里 any = every，全称。读成「存在某一对」整题就废了。
positive slope 严格 > 0。水平线斜率为 0，不算；垂直线斜率不存在，也不算。
does not even exist 2 points ... 说的不是「输入点数少于 2」，是「凑不出任何一对正斜率」。[(0,0),(1,0),(2,0)] 三个点，答案是 0。

那个会让你挂测试的 tie-break

✗ 错误写法
sort by x asc,
tie → y ascending

随机对拍 3000 组：751 组答案错误。

反例 [(0,3),(3,0),(1,0),(1,2)] → y 数组 [3,0,2,0] → LIS = 2，选中的是 (1,0) 和 (1,2)，同一个 x，垂直线。正确答案是 0，它返回 2。

✓ 正确写法
sort by x asc,
tie → y descending

同样 3000 组：0 组错误。

同 x 的点 y 变成递减，严格递增的 LIS 就物理上不可能同时选中它们。用排序把非法组合直接排除掉——这个技巧值得单独记住。

根因是英文没读准。把约束陈述成「if x₂ > x₁, then y₂ > y₁」只覆盖了一半——它没有说 x₁ ≠ x₂ 本身也是硬约束。条件漏了一半，排序规则就跟着漏。这就是 Pass 2 存在的全部理由。

// 完整约束（两条，缺一不可）
// 1) 集合内任意两点 x 互不相同
// 2) 按 x 升序排列后，y 严格递增

sort(points, by x asc, tie: y desc);   // ← tie 方向是关键
int[] ys = points.map(p -> p.y);
int len = lengthOfStrictLIS(ys);       // tails + binarySearch, O(n log n)
return len < 2 ? 0 : len;              // ← Note 那条边界
06

Pass 5 只记两栏

栏一 · 逻辑词踩坑
  • 今天哪个限定词读偏了
  • 它导致代码里哪一行写错
  • 补进第 03 节那张表
不记 slope 这种实义词。刷够题自然会，专门背是浪费时间。
栏二 · 口述卡壳短语
  • Pass 4 里说不出来、绕过去的那句
  • 写下你本来想说的中文
  • 再写一遍地道说法，下题直接用
这一栏比栏一更重要——面试里讲不清楚，题做对了也挂。
这套流程的赌注只有一个：先预测，再验证，学习效率远高于先看答案再理解。速读模版负责产生预测，精读负责提供反馈信号，口述负责把已验证的理解固化下来。顺序换了，三样都失效。
