三层优化，每层砍掉一样东西

找两个没有共同字母的单词，使长度乘积最大。三个版本算的都是同一个答案，差别在于「做了多少无用功」—— 右边的计数器直接对比。

三层分别砍掉了什么

① 位运算判「有无共同字母」        把每次比较从 O(m) 降到 O(1)
   mask |= 1 << (c - 'a')        26 个字母压进一个 int 的低 26 位
   (maskA & maskB) == 0          & 找交集,全 0 就是没有共享

② mask 预处理成数组               同一个词的 mask 不再被重算 n 次
   开头一次算完 int[] masks       字符扫描从 O(n²·m) 降到 O(n·m)

③ 降序排 + prod <= largest 就 break   砍掉大量根本不可能更优的配对
   排序保证内层 j 越往后词越短,prod 单调递减
   当前这个都打不过已有答案 ⇒ 后面全不用看 ⇒ break 整段

为什么 ③ 是 break 不是 continue：continue 只跳过这一个，break 才是砍掉一整段内层循环。这个区分就是剪枝的全部。

循环顺序也是设计过的：i 从 1 外层、j 从 0 到 i-1，保证先试长的组合，largest 尽早变大，后面的剪枝才砍得多。

一个细节：③ 里可以直接写 largest = prod 而不用 Math.max —— 因为有了 if (prod <= largest) break，能走到这行的 prod 必然大于 largest。剪枝条件顺便替你做了 max 的活。没剪枝的版本就必须用 Math.max。

复杂度：三个版本最坏都是 O(n²)，②③ 改善的是常数和期望。真正必须做的是 ①（干掉那个 m），②③ 是加分项。
