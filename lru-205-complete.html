map 存的不是"位置"

链表没有下标、没有"第几个"。map 存的是那个方框本身在内存的哪儿（一个引用）。拿到引用，prev 和 next 就在手上了 —— 它在队伍里排第几，没人关心也没地方记。

如果 map 只存 value 会怎样

写法后果
Map<K, Node> ✓直接把方框交给你，prev/next 立刻可用 → 摘和挂都是 O(1)
Map<K, V> ✗只给内容，不知道是哪个方框，得从 head 一个个走过去比对 → O(n)

一个字的差别，决定了整道题成不成立。

为什么 node.next 不会 NPE

    
点号左边那个东西不能是 null，右边随便。

    
node.prev.next = node.next —— 左边的 node.prev 不能是 null（所以要判断），右边的 node.next 只是被读出来，是 null 也照样赋过去，完全合法。

字段名要全文统一

    
Node 里声明 prev，那 remove / append 里也得写 prev。写成 pre 又在别处用 prev，直接编译不过。

    
没用 dummy 哨兵的代价

    
这份答案没有虚拟头尾节点，所以 remove 里有四个边界判断、append 里有 head == null 特判。用 dummy 双哨兵能把这些全消掉 —— 两种都对，知道差别就好。
