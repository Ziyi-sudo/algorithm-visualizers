course schedule ii · 下标 vs 值

arr[0] 和 inDegree[0] 里的 0，
是两个完全不同的 0

同一段代码里有两个数组，它们的下标含义毫无关系。arr 的下标是「第几个数」，inDegree 的下标是「哪门课」。把前者的值当成后者的下标用，才是正确的桥梁。

arr — 题目给的一对

下标只表示「第一个数 / 第二个数」，跟课程编号无关

inDegree — 我自己开的账本

下标就是课程编号，值是「这门课还欠几门先修」

那行为什么写错

inDegree[0]++ 写死了 0 —— 不管这一对是什么，永远在给课程 0 加账。四条边跑完，inDegree[0] 变成 4，其余全是 0。
inDegree[cur]++ cur 是从 arr[0] 取出来的值。这一对是 [1,0] 就动课程 1，是 [3,2] 就动课程 3。

「我现在指的是谁」不需要去查 —— 是你自己在下标里指定的。写 inDegree[0] 就是在说「我要动课程 0」，写 inDegree[cur] 就是「cur 是多少就动谁」。数组的格子位置从头到尾不变，变的只是格子里的数。

防这个坑的习惯：提取之后就只用变量名。既然已经写了 int cur = arr[0];，下面就别再出现 arr[0] 或裸的 0 —— 混着写正是手滑的来源。

示例：numCourses = 4，prerequisites = [[1,0],[2,0],[3,1],[3,2]]
