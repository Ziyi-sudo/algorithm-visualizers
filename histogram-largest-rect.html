弹出的那一刻，两个边界同时到齐

栈里装的是下标，对应高度从栈底到栈顶严格递增。当某根柱子被弹出，它的右边界就是触发弹出的 i，左边界就是弹完后露出来的新栈顶——两个边界在同一瞬间凑齐，所以一趟就够。

数据组

单调栈 · 装的是 下标（左＝栈底＝矮，右＝栈顶＝高）

三个数字是怎么来的

height —— 被弹出那根的高度

int height = array[stack.pollFirst()];

矩形的高，由被弹出的那根决定，不是当前这根 array[i]。这是最容易搞反的一处：我们不是在为 i 算矩形，是在为刚被 i 挤掉的那个人算矩形。

右边界 —— 就是 i

它被弹出的原因就是 array[i] < 它的高度。所以 i 正是「它右边第一个比它矮的位置」。矩形延伸到 i-1 为止，碰到 i 就撞墙了。

末尾那根高度 0 的哨兵（i == array.length 时 cur = 0）的作用就在这里：让栈里剩下的人都能撞到一堵墙，否则递增序列永远没人来弹它们，{1,2,3} 会返回 0。

左边界 —— 弹完之后露出来的新栈顶

int left = stack.isEmpty() ? 0 : stack.peekFirst() + 1;

栈里的高度是严格递增的，所以新栈顶一定比刚弹掉那根矮 —— 它就是「左边第一个比它矮的位置」。而它俩之间夹着的人，早就被更早的弹出清光了，中间不可能藏着更矮的。

新栈顶 = 左边第一个更矮的下标
left  = 新栈顶 + 1          ← 矩形从它的右邻居开始
宽    = i - left            ← 右边界 i 不含在内，所以直接相减

栈空时：左边一个更矮的都没有 → 可以一路铺到 0 → left = 0

如果换成记 lb = 新栈顶（不 +1），那宽度就要写成 i - lb - 1。两种写法完全等价，官方答案选了前者，少一个 -1。
